## 0. 我们从哪开始的

有个能跑的纺织客服 Demo（Python + LangGraph）：你在聊天框问"T400 黑色多少钱"，它会查产品库报价；
说"我要下单"，会走人工审批再写订单。技术不差，但它有几个"不像正经产品"的地方：

- 没有真正的账号：全靠请求头里自己报个名字（X-User-Id），报谁都行，大家历史还混在一起
- 没有"多轮对话"概念：历史就是一根流水，聊啥都串
- 界面是深色 + 蓝按钮的"程序员皮肤"
- 部署？容器起来了表是空的，前端还没打进去——上了服务器就是空转

接下来这一个多星期，我们把它改成了：**能注册登录、能开多个对话、客户能查自己订单、界面能看、已经挂到公网能体验**的"正经 Agent 产品"。

## 1. 为什么先做登录，不做界面

你最开始提了两个愿望：登录注册 + 改界面。我说先做登录，原因用一个比喻：

> 界面是房子装修，登录是"给房子装门和钥匙"。
> 没有门，你装修时都不知道住进来的人长啥样——顶栏要不要显示名字？管理员入口给谁看？
> 装了门，装修才有对象。

而且装门的零件（JWT、角色、账号表）都是后端地基，做完登录，"谁能看什么"就一劳永逸了，
后面界面照着角色画就行，不用返工。**先有身份壳，再装修内部**——这是第一个经验。

## 2. 登录这坨是怎么长出来的

### 密码为什么不能存明文
你要是把用户密码原样存数据库，数据库一泄露，所有账号裸奔。正确做法：

**bcrypt** 干了两件事：给你的密码**撒一把随机盐**（每个用户盐不同），再**来回搅拌很多次**（成本因子 12，
大概 0.2-0.3 秒）。存库的是搅拌结果。验证时再用"你输入的密码 + 库里存的盐"拌一遍，比一比。
同密码不同人，存出来的串都不一样——这就是为什么不能反过来算。

### JWT 是什么
登录成功，服务器发你一张"通行证"（token），里面写着你是谁、啥角色、什么时候过期。
你每次请求带着它，服务器**验签**（我们用的密钥签名，谁改过内容签名就对不上），不用每次查数据库确认你是谁。
这就是"认证"。

### 角色和越权
注册接口只允许注册成普通客户。想当管理员？只能由 `create_admin.py` 脚本用你配的环境变量创建——
**"注册的入口永远不能自己选角色"**，否则谁都能注册个管理员，登录系统就是个摆设。

### 还有一个老习惯要砍
以前"没登录也让你聊，身份=你自报的名字"（guest 回退）。砍掉：**没 token 一律 401**。
道理很简单：门都装了，就不能让没钥匙的人从窗户爬进来。

## 3. 换皮大战：玻璃 UI 是怎么调出来的（真实迭代史）

你其实陪我调了好几轮，这段最有意思的是"用户反馈 = 验收信号"：

| 我干了啥 | 你的反馈 | 我学到 |
|---|---|---|
| 把蓝色换成浅蓝、面板改半透明 | "没变化" | **面板不透 + 背景没东西，玻璃看不出来**——玻璃要有"内容在背后可糊" |
| 加了光晕背景、面板留缝 | "有一点变化了，要圆角立体感" | 方向对了，继续 |
| 做成分离的圆角浮层 + 顶部高光 | "可以" | ✅ 立体感来自：`inset 顶部高光 + 柔和投影` |
| 彩色全部改淡、加"海浪"动画 | "不太看得出来" | 光晕太含蓄 = 等于没有 |
| 海浪提速 + 加横向波光带 | "不太对，回上一版" | **动效宁可克制**，9-20 秒一循环是"活"，2 秒一转是"烦" |

几个技术点，白话讲：
- **圆角/阴影/色板只改一处配置**（tailwind.config），全站生效——这就是"设计系统"偷懒的正确姿势
- 淡蓝按钮 + **深藏青字**：颜色淡≠看不清，把字调深，对比反而比"浅蓝+白字"更好
- 背景那团光：4 个半透明光斑做**平移缩放动画**（GPU 处理，便宜），系统开了"减弱动态"就自动慢下来

## 4. 会话隔离 = 把一根流水账，拆成多本笔记本

之前所有人的聊天记录是一根"全部消息流水"，按人切。但一个客户今天问面料、明天要下单，
都塞一个"本子"里，切不回上下文。

现在：每个客户可以**开多本笔记本（会话）**。规则：
- 每本有个名字（自动取你第一句话的前 18 个字）
- 发消息时带"我在哪本笔记本里"（session_id）
- 服务器查历史 = 只翻这本（user_id + session_id 两个条件）
- **别人的本子你翻不了**——查询强制带 user_id，跨用户直接 404

老数据怎么办？给老流水补一个默认会话 `default` 列，一锅端放进去（`ALTER TABLE ... IF NOT EXISTS`，
跑一万次也不报错，这就是**幂等迁移**）。

## 5. 两个窗口两个身份的秘密

你当时发现：开一个窗口登录客户，再开一个窗口登录管理员，**客户窗口也被顶成管理员了**。

原因一句话：token 存在 `localStorage` 里，而 localStorage 是**整个网站共享的公共储物柜**——
两个窗口共用一格，后放进去的盖掉前面的。

修法：改存 `sessionStorage`（每人一个储物格，窗口关了格子就没了）。
代价：关标签 = 登出。换来：两个窗口各登各的号。

> 知识点（面试能吹）：localStorage = 持久 + 跨标签共享；sessionStorage = 随标签页 + 独立。
> 选哪个，取决于你要"共享登录"还是"多身份并存"。

## 6. 最精彩的一段：下单为什么"没调下单工具"（侦探故事）

### 案发
客户把流程走完了：下单 → 补收货信息 → 说"确认"。日志却显示：

```
[Supervisor] → 下单 Agent     ← 对，进了下单
[Supervisor] → 下单 Agent     ← 对，补信息也进了下单
[Supervisor] 延续 → 售前        ← ？？"确认"被送去售前了
```

于是 create_order 永远没被调，订单挂半路。

### 推理（像看日志破案）
Supervisor 是"路口交警"，它决定消息走售前/下单/售后。它的规则里有很重要的一条：
"客户上一轮在下单流程里，现在说『确认』——继续送下单。"

这条规则要看**"上一轮在哪个流程"**（query_type），而这个值存在数据库记忆里。
好，问题来了：**网页聊天走的是流式接口（/chat/stream），而流式接口从来不把"上一轮在哪个流程"写回记忆！**
另一条非流式接口（/chat）写了。两条路只修了一条 → 网页用户永远处于"失忆"状态：
交警以为客户上一轮在售前，说"确认"就当作闲聊/售前问题处理了。

### 修复（三层保险）
1. **补记忆**：流式接口结束时，把"当前在哪个流程"也存进数据库（治好失忆）
2. **加规则**：只要"上一轮在下单 + 上一句 AI 在问你要信息 + 你没说不要" → 无条件送回下单，
   不劳烦 LLM 猜（你补的地址电话全是数字，"确认"也不是什么明显的下单词）
3. **上单测锁死**：纯数字补全 → 应该送下单；说"不用了谢谢" → 不该送下单。以后谁敢改坏，测试立刻报警

> 一句话总结这个 bug：**两个入口行为不一致 + 跨轮状态没持久化 = 隐形的状态机失忆**。
> 面试讲这个，能体现你会"看日志 → 定位两处分叉 → 三层修 → 单测锁行为"。

## 7. Rerank 开关：服务器很贵的，精排可以省

RAG 检索本来是三层：向量搜 → 关键词搜 → **精排（rerank，一个 ~1GB 的模型）把候选里最好的几个挑最前**。
精排确实能让结果更准（MRR 0.849 → 0.959），但它是"锦上添花"：
向量+关键词混排本身命中率已经 100%（85 题评测）。

服务器内存预算紧张？给它加开关 `RERANK_ENABLED`，默认关：
- 关 = 只跑混排，省 ~1GB 内存、零额外费用
- 评测脚本不受影响（它显式传参做对比），想开回来 .env 改 1 重启即可

> 工程思路：**一个功能要不要"默认开着"，看它是不是每个场景都必要。**
> 非必要的重活，宁可做成开关，也别默认拖垮所有用户。

## 8. 上线那两天：一串全是"看着没事、跑起来就炸"的坑

### 8.1 zip 打包：你以为排干净了，结果 400MB
第一次打部署包 397MB——漏排了 `.uv-cache`（792MB）和 `web/.npm-cache`（38MB）。
**教训：打包前 `du -sh` 先看哪些目录大，打完再 `unzip -l | sort -nr | head` 复查最大的文件。**

### 8.2 容器"空转"三连
在服务器 `docker compose up` 后 healthz 全绿，但：
- 表是空的 → 入口脚本先等数据库，再建表 + 建管理员 + 灌知识索引，最后才启动服务
- 找不到 `src` 模块 → `python scripts/xxx.py` 时 Python 只认识脚本自己的目录，
  脚本里要手动把项目根插进模块搜索路径
- 产品表是 0 行 → 我打包时把 `data/*.db` 当"本地数据"排掉了，**281 条产品正藏在里面**！
  改成导出成 `sql/001_products.sql` 种子，容器首次启动自动灌进数据库

### 8.3 下载模型：镜像自己把自己禁网了
容器镜像里设了"离线模式"（HF_HUB_OFFLINE=1）想省事，结果**构建时下载模型那一步也被禁网了**。
加上 HuggingFace 换了新存储格式（Xet），镜像站都被绕过。解法：
下载那行临时 `HF_HUB_OFFLINE=0` + `HF_HUB_DISABLE_XET=1`，直连官方源成功。
顺手把模型下载放到"拷贝代码之前"——以后改代码重构建，不用再重下 0.4GB 模型。

### 8.4 白屏 + 发不出消息：crypto.randomUUID
上线后页面能登录，但发"你好"没反应，控制台报 `crypto.randomUUID is not a function`。

原因是个冷知识：`crypto.randomUUID` 只存在于**"安全上下文"**——要么 HTTPS，要么 localhost。
本地开发是 localhost，没事；公网 `http://IP` 明文访问，浏览器直接不给你这个函数 → 前端崩。

修法：包一个 `uuid()`：能用 randomUUID 就用，不能用就退回 `crypto.getRandomValues`
（这个 API 在明文 http 下也给你用）手动拼 UUID。
**教训：凡依赖"安全上下文"的浏览器 API，都要兜底；根治办法是上 HTTPS。**
