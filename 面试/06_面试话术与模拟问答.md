## 一、自我介绍（1 分钟版）

> 结构：我是谁 → 我做了什么 → 我做的东西有什么亮点 → 为什么适合这个岗位

**话术（可直接背）**：
> 面试官您好，我做 LLM 应用 / Agent 方向的开发。最近完整做了一个纺织 B2B 智能客服 Agent 项目：
> 基于 LangGraph 把一次咨询编排成「改写查询 → 混合检索 RAG → Supervisor 意图路由 → 售前/下单/售后三个子 Agent → 双层安全审核」的有向图。
> 三个我认为最能体现能力的点：
> 第一，**HITL 人工审批**——下单这类高风险操作用 LangGraph 的 interrupt 把图挂起，人工审批通过才真正写库，这里我处理了重放语义、确定性生成这些细节；
> 第二，**评测驱动改进**——我实现了一套 LLM-as-Judge 四维评分体系，并且它真的抓到了"答非所问"的 bug，我修完 prompt 后通过率从 10/11 提到 11/11；
> 第三，**工程化完备**——多用户隔离、三层记忆、自研轻量 MCP 工具层（线程安全+崩溃自愈）、节点事件和 token 双路 SSE 流式，66 个单元测试全绿。
> 我对 Agent 的规划、工具调用、RAG、评测这些方向都有从代码到原理的实践，很希望加入贵司继续做 Agent 方向。

**要点**：1 分钟内，讲"项目 + 三个亮点 + 一句自荐"，不要展开技术细节（细节留给追问）。

## 二、项目介绍（3 分钟深度版："请详细讲讲你的项目"）

按这个顺序讲（对应文档 02/03）：

1. **业务背景**（30s）：纺织 B2B 工厂客服，客户在聊天里完成询价/知识问答/下单/售后四件事；高频重复咨询由 AI 消化，销售精力给高价值客户。
2. **系统架构**（60s）：画图。四层——FastAPI 入口 → LangGraph 图编排（8 节点，Supervisor 三分支）→ MCP 工具层（3 个子进程 Server）→ 存储层（SQLite/ChromaDB/Redis/本地模型）。每层一句话。
3. **核心链路**（60s）：一条消息的旅程：身份校验 → 记忆加载 → 挂起守卫 → 改写 → 检索 → 路由 → 子 Agent（ReAct 循环 + 工具）→ 审核 → 返回。重点讲 RAG 管线（向量+BM25+RRF+Rerank）和 HITL（interrupt 挂起 → 审批 → resume 重放写库）。
4. **亮点与数据**（30s）：评测三件套（85 题消融 / 11 题端到端 / Judge 四维）+ 11/11；多用户隔离；流式体验。
5. **不足与改进**（30s）：主动讲已知边界（process 内 checkpointer、审批无鉴权、stdio 串行），每一句都带"生产怎么改"。

> 讲完后大概率被追问的点（提前备好）：HITL 重放语义、为什么温度 0、RRF 为什么用排名、MCP 自愈怎么做、token 流怎么穿层、评测怎么抓到 bug。都在 03/04 文档里。

## 三、STAR 故事卡（准备好 3 个故事，随时取用）

### 故事 1：评测驱动改进（最能证明"你解决过真问题"）
- **S**：端到端评测只有规则断言，测不出质量问题。
- **T**：加 LLM-as-Judge 四维评分，找出质量缺陷并修掉。
- **A**：写 eval_judge.py（维度设计、通过标准、共用用例集）；首轮跑出 10/11，裁判指出"知识问答过于依赖表格、纯文本答非所问"；定位到 agent prompt 和 render 提示两处，加"先给结论再查价"和"正文不依赖表格"。
- **R**：11/11 通过，Judge 均分 relevance 5.0 / overall 4.82；沉淀了"评测 → 定位 → 修复 → 复测"的方法论。
> 加分句：**"评测不是用来证明我做得好，是用来抓我做得不好的地方。"**

### 故事 2：HITL 的实现与踩坑（最能证明"技术深度"）
- **S**：AI 直接写订单，有真实资金风险；且要实现"执行过程前端可见"。
- **T**：给下单加人工审批 + 节点事件流式。
- **A**：interrupt + checkpointer + Command(resume)；发现 async astream 与同步 interrupt 不兼容且 checkpoint 不落盘 → 改同步 stream + 后台线程 + 双队列桥接；处理重放幂等（temperature=0、register_pending 覆盖）。
- **R**：下单状态机完整可靠：挂起 → 审批列表 → 通过才写库 → 结果回写记忆；挂起守卫防重复下单。
> 加分句：**"HITL 的坑不在 interrupt 本身，而在'恢复是重放'——所有前置节点必须幂等、所有 LLM 决策必须确定。"**

### 故事 3：生产化改造（最能证明"工程意识"，对应 docs/UNDERSTANDING 的改造清单）
- **S**：Demo 版多用户串记忆、SQLite 连接泄漏+并发锁、裸线程、MCP 串线/僵死、下单无审批。
- **T**：按优先级 P0-P3 生产化改造。
- **A**：user_identity 单一校验源；sqlite_utils（WAL+busy_timeout+必关连接+订单号防撞）；任务队列替代裸线程；MCP 加锁+超时+自愈；HITL；节点流式；LLM-as-Judge。
- **R**：66 个单测全绿、压测 20 线程 400 并发写 0 失败、评测 11/11、CI 自动回归。
> 加分句：**"改造过程中最受益的是'把每一个偶发问题都变成可复现的测试'。"**

## 五、反问环节（面试官问"你有什么想问的"）

> 一定要问！问题质量 = 你对岗位的认真程度。

**推荐问题（按场合选 2-3 个）**：
1. 「贵司的 Agent 目前在哪个阶段：demo、内部工具还是直面客户？最头疼的问题是评测还是成本还是稳定性？」（体现你在想生产落地）
2. 「团队的 Agent 技术栈是什么？LangGraph、自研还是有产品套件？工具层走 MCP 吗？」（体现你懂生态）
3. 「这个岗位进去后第一个项目大概是什么方向？我现在准备的 RAG/HITL/评测经验哪块最相关？」（体现你已经在想怎么干活）
4. 「线上 Agent 的错误率怎么监控和回归的？有没有 eval 集/线上 A/B？」（体现工程意识）

**避免问**：加班吗、年终奖多少（除非终面 HR）；"你们用不用 ChatGPT"（太外行）。

## 六、常见面试节奏模拟（完整过一遍）

**Round 1：开场 5 分钟**
- 自我介绍（1 分钟版）→ 面试官根据项目介绍追问。

**Round 2：项目深挖 25 分钟（最高概率被问清单）**
1. 讲讲整体架构？→ 01 文档架构图
2. 你画一下 LangGraph 的图？节点都有啥？→ 01/02
3. 为什么用混合检索？RRF 怎么融合？→ 03 机制 3
4. HITL 怎么实现的？挂起时订单写了吗？恢复了去哪？→ 03 机制 5（重点！）
5. 为什么下单 LLM 温度 0？→ Q40
6. MCP 线程安全和自愈怎么做的？→ Q54
7. token 流式怎么穿透的？为什么放后台线程？→ Q62-65
8. 审核为什么两层？fail-open 还是 fail-closed？→ Q78-81
9. 记忆三层分别干嘛？偏好提取为什么异步？→ Q70-74
10. 评测怎么做的？抓没抓到过 bug？→ Q94-100（讲 10/11 故事！）

**Round 3：八股 15 分钟**（05 文档过一遍重点）
- Transformer/Attention、temperature、幻觉、RAG 全流程、ReAct、Function Calling 的坑、上下文管理、Agent 安全。

**Round 4：手撕代码 10 分钟（如果面算法/工程岗）**
- 大概率不是纯算法，而是：写个 ReAct 循环 / 设计个 RAG 管线 / 写个工具调用循环 / 写个限流器 / 画个系统设计。
- 准备：05 文档 Q66-67 的两个口述代码 + 04 文档第十四组的系统设计答法。

**Round 5：反问 5 分钟** → 用第五节的问题。

## 八、心态提示

1. **这个项目的题材（客服/下单/HITL/多 Agent）非常接近真实 Agent 落地场景**，面试官大概率懂行——你讲的每个"为什么"都能被验证，所以别背答案、按"我当时为什么这么选、踩了什么坑、换你会怎么做"来讲。
2. **被问住不可怕**，可怕的是不会还硬编。标准应对：「这个问题我目前的理解是 X（给一个合理思考路径），如果要深入，我倾向先看资料再验证——比如 Y 方向」。诚实 + 思路 = 通过。
3. 记住你最值钱的三句话：
   - 「下单不是 AI 一步到位，是 interrupt 挂起 + 人工审批 + resume 重放——高风险动作必须人审。」
   - 「评测不是证明我做得好，是抓我做得不好的地方，它真抓到了。」
   - 「这个项目每个机制我都能讲出'为什么这么设计'和'生产上怎么演进'。」
