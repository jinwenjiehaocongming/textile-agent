## 二、面试复习路线（按剩余时间）

### 有 3~5 天
1. 精读 `01` + `02`，**合上文档在白板上画出流程图**（入口→改写→检索→路由→三分支→审核→返回；HITL 挂起/恢复）。
2. 精读 `03` 的前 6 个机制（图、路由、RAG、HITL、MCP、流式）——这是面试官最爱深挖的。
3. 用 `04` 做自我模拟：每题先自己答，再看答案，重点练「追问链」（答完第一层要能接第二层）。
4. 八股过 `05`，标记自己不会的，逐个背。

### 有 1~2 天
1. 背熟 `01` 的架构图 + 文件地图（每个文件一句话）。
2. 背熟 `02` 的售前流程和下单 HITL 流程（含行号）。
3. 背熟 `04` 的前 30 题（标了 ⭐ 的）。
4. 过一遍 `06` 的话术，练 1 分钟自我介绍。

### 面试当天早上
- 快速过 `06` 的自我介绍 + `01` 架构图。
- 记住三个"杀手级叙事"：
  1. **HITL 人工审批**（interrupt + checkpointer + Command resume）
  2. **评测驱动改进**（LLM-as-Judge 抓到"答非所问"→ 改 prompt → 11/11）
  3. **真 token 流式**（ContextVar + SSE，首包延迟决定要不要做流式）

## 三、项目一句话定位（背熟）

> 一个**纺织 B2B 智能客服 Agent**：用 LangGraph 把一次咨询编排成
> 「改写查询 → 混合检索(RAG) → Supervisor 意图路由 → 售前/下单/售后三个子 Agent 分流 → 双层安全审核」的有向图；
> 下单走 **HITL 人工审批**（interrupt 挂起，审批通过才写库）；
> 每个图节点和最终回复 token 经 **SSE 实时流式**推给前端；
> 带 **多用户隔离、三层记忆、MCP 工具层、LLM-as-Judge 评测体系**，端到端 11/11 通过。

## 四、面试官可能的开场三连问（先把这三个答好）

1. **"介绍一下你的项目"** → 用 `06` 的 1 分钟版话术。
2. **"为什么用 LangGraph 而不是直接调 LLM？"** → 状态、分支、工具循环、HITL 挂起需要编排框架；直接调 LLM 只能一问一答，无法多步工具循环 + 人工中断恢复。
3. **"这个项目你遇到的最大挑战/最有亮点的设计？"** → HITL 人工审批（technically deep）+ 评测驱动改进（有数据支撑）。

## 五、诚实边界（面试被追问时如实说，别被问倒）

提前背熟 `04` 最后「项目缺点与改进」章节，面试官一定会问：
- checkpointer 是进程内 MemorySaver，重启会丢挂起的审批 → 生产换 Postgres/Redis 持久化。
- 审批端点没鉴权 → 生产接管理员登录。
- MCP 走 stdio 子进程 + RLock 串行 → 高并发换 HTTP/Streamable HTTP 传输。
- 评测裁判与作答是同族模型 → 自评偏差，可换异构模型交叉打分。
- 单进程部署，多 worker 时 embedding/rerank 模型重复加载 → 下沉独立推理服务。

> **面试心法：与其背答案，不如把上面每一条都变成"我知道，而且我知道怎么改进"的自信表达。**
> 面试官要的不是完美项目，而是一个**真的吃透了自己代码**的人。
