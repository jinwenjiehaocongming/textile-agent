# 01 项目架构与文件地图

## 一、项目是什么

**宏润纺织 B2B 智能客服 Agent**：面向纺织面料 B2B 客户（买家直接找工厂问价、下单、售后）的 AI 客服系统。

客户在聊天窗口问：
- 「T400 黑色多少钱一米」→ **售前**（查产品库报价）
- 「羽绒服用什么面料好」→ **售前知识问答**（检索面料知识库）
- 「帮我下单 1000 米」→ **下单**（收集信息 → 确认单 → 人工审批 → 写订单）
- 「收到的布有破洞」→ **售后**（查订单 → 对照退货规则 → 生成退款工单）

### 核心特征（README.md + 代码提炼）
1. **多 Agent 架构**：LangGraph 编排，Supervisor 三分支路由（售前/下单/售后），状态机 + LLM 意图分类
2. **混合检索 RAG**：ChromaDB 向量 + BM25 关键词 + 加权 RRF 融合 + CrossEncoder Rerank
3. **结构化产品查询**：SQLite 281 条产品，关键词匹配 + 计分排序（MCP 工具）
4. **HITL 支付审批**：下单经 LangGraph `interrupt()` 挂起，销售人工审批通过才写库
5. **节点事件流式**：图执行过程经 SSE 实时推给前端
6. **真 token 流式**：最终回复 token 逐字推送（ContextVar + llm.stream()）
7. **双层审核**：规则快速拦截 + LLM 安全审查（所有回复必过）
8. **三层记忆**：Redis 热缓存 + SQLite 持久化 + ChromaDB 偏好提取
9. **多用户隔离**：`X-User-Id` 请求头按用户隔离历史/偏好/订单
10. **评估体系**：检索消融评测 85 题 + 端到端规则评测 11 题 + LLM-as-Judge 四维评分

## 二、技术栈（面试必答）

| 层 | 技术 | 作用 |
|----|------|------|

| 缓存 | Redis（未运行时降级内存 dict） | 会话热缓存 |

| 可观测 | logging（stderr + 滚动文件）/ LangSmith trace | 日志 + 追踪 |

## 五、数据模型（面试可能问数据库结构）

**products.db / products 表**：id(货号 Pxxx)、name、color、width(门幅)、weight(纱支)、stock(库存米)、moq(起订量)、price(元/米)、delivery_days(交期)。

**orders.db / orders 表**：order_no（`ORD-YYYYMMDD-HHMMSS+微秒6位+随机4位`，防同一秒撞 UNIQUE）、customer_id、product_id、product_name、color、quantity、unit_price、total、status（待付款）、created_at、phone、address、delivery_date。

**orders.db / refunds 表**：order_no、reason、status（待审核）、created_at。

**data/users/<user_id>/chat.db**：conversations(id, role, content, created_at) + profile(key, value, updated_at)（存 last_query_type）。

**data/users/<user_id>/chroma/**：ChromaDB collection `user_memory`，documents 即偏好文本。

## 七、两个模型 + 三种 LLM 的使用场景（追问高频）

| 对象 | 是什么 | 用在哪 |
|------|--------|--------|
| `llm` | 主 LLM（DeepSeek，temperature=0.3, timeout=30） | 售前 Agent 对话（`agent.py` 的 `agent_node`） |
| `cheap_llm` | 轻量 LLM（temperature=0.1, timeout=15） | 改写检索词、Supervisor 分类、安全审核、偏好提取、评测裁判——**便宜快速的任务** |
| `order_llm` | 下单 LLM（temperature=0） | 下单 Agent（**温度 0 保证 interrupt 重放时决策一致**，见 03 文档 HITL 章） |
| `after_sales_llm` | 售后 LLM（temperature=0） | 售后 Agent |

> 面试点：**为什么下单/售后用 temperature=0？** 因为它们在 HITL 场景下会被「重放」（LangGraph interrupt/resume 会重新执行到挂起点的整条路径，见 03 文档），温度 0 保证同输入同输出、重放时不会在 collect 订单信息阶段又说一遍"请提供电话"之类的废话或产生不同决策。

> 面试点：**为什么区分 llm / cheap_llm？** 意图分类、改写、审核这类"判断型"任务不需要高温度创造性，用更快更稳的低温模型省成本省延迟；客户可见的最终回复用主模型。

> 面试点：**LLM 为什么懒加载（模块级 `__getattr__`）？** import 时不实例化（实例化需要 API key，CI 或无 .env 环境会导入即崩）；首次访问属性才创建。这是工程细节，能体现你注意过 import 副作用。
